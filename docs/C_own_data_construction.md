# C. 자체 데이터 구축

> 담당 영역: §10-C. 오늘 목표 = 포맷을 ACI-Bench에 맞춰 공식 스코어러를 그대로 쓰게 하고, 음성 라벨 채점법의 함정을 미리 잡고, 사람 작성 분량을 현실적으로 재산정.

## C-1. 스키마 — ACI-Bench에 정렬 (공식 스코어러 재사용 목적)

자체 데이터는 ACI-Bench 컬럼을 그대로 따른다:

```
dataset, encounter_id, dialogue, note
```

- `dialogue` 화자태그는 ACI 포맷 `[doctor]` / `[patient]` / `[patient_guest]` 사용.
- 이렇게 하면 `data/aci-bench/evaluation/evaluate_fullnote.py`(공식 MEDIQA-Chat 스코어러)를 **자체 데이터에도 그대로 적용** 가능 → 자작 채점 스크립트 불필요(§D 재사용).

## C-2. 함정셋 음성 라벨 — exact-match 채점 불가 (설계 함정)

계획서 §3-2: 함정 케이스에 *"나오면 안 되는 문장"*을 음성 라벨로 명시. **주의**: 생성 노트는 paraphrase하므로 금지 문장이 글자 그대로 안 나온다. 문자열 매칭으로 채점하면 환각을 놓친다.

→ 음성 라벨을 **두 필드로 분리 설계**:

```
forbidden_claims : [ "환자가 흉통을 부인했다", ... ]   # 의미 단위(자연어 명제)
unknown_required : [ "가족력", "복약 순응도", ... ]      # 미확인 처리돼야 할 항목
```

- 채점은 **entailment / LLM-as-a-judge**(§D)로: "생성 노트가 forbidden_claim을 함의하는가?" Yes → 환각 1건.
- `unknown_required` 항목이 미확인 표기 없이 채워졌으면 → 누락회피 실패 1건.
- 이 설계가 계획서 §5-3(환각률·누락률의 자체 적용)과 정합.

## C-3. 규모·분량 현실성 — 파일럿 실측 필요

계획서: 잡음 25~30건 + 함정 20건 = **약 50건, 정답 SOAP 노트를 사람이 직접 작성**(LLM 위임 금지 — 채점 순환오류 방지, 이 원칙은 타당).

- ACI-Bench 노트 중앙값 = **415단어**. 50건 × 415단어를 의료 배경 없는 팀이 직접 쓰는 건 큰 부담.
- **오늘 미완**: 파일럿 1건을 실제로 작성해 소요시간을 재고 §9 일정을 재산정해야 함(플랜의 verify 항목 중 유일한 미완).
- 완화 옵션(회의 안건): ① 잡음셋은 full-visit 대신 **단일 섹션 집중**(짧게) ② 함정셋은 ACI 기존 노트를 **변형**해 정답 작성 부담↓ ③ 규모를 25→15로 축소하고 유형당 품질↑.

## C-4. 한국어 데모 (계획서 §3-2 (3))

- 5~10건, 발표 시연용. 잡음·함정 일부와 연계.
- 평가는 영어 기반(국제 검증셋 있음), 한국어는 **정성 시연만**(계획서 §11 결론과 동일). LLM이 영어로 개발돼도 한국어 대화→한국어 SOAP는 작동하나, **채점 기준이 없어 정량 불가**.
