# 프론트엔드 점검 & 발전 로드맵 (2026-07-18)

담당: 송윤. 대상: `web/` (FastAPI + 단일 HTML 대시보드).

## 1. 점검 결과 — 발견·수정 완료

| 문제 | 증상 | 수정 |
|---|---|---|
| **재생성 레이스** | 결과가 뜬 뒤 다시 생성하면, 이전 실행의 늦은 judge/번역 응답이 새 화면을 덮어씀 | 실행 토큰(RUN)으로 낡은 응답 폐기 |
| 단계 라벨 표류 | 결과 표시 후 드롭다운을 바꾸면 패널 라벨이 결과와 어긋남 | 생성 시점 단계로 고정 |
| judge 배너 오판정 | `A: ASSESSMENT` 배너줄을 문장으로 판정→환각률 인플레 | split_sentences에서 배너 스킵 (배치 채점에도 영향) |
| 대화 번역 환각 | 초단문("sure.")에 임상 서사 창작, 반복 루프, 지시문 부정합 | 백채널 사전+초단문 스킵+폭주 가드+대화 전용 지시문 |
| S/O/A/P 구역 실종·병합 | tagger 한계로 O 실종·A&P 한 덩어리 | 배너 기반 분할로 4구역 보장(빈 구역 명시) |
| 소형모델 반복 생성 | 노트 2회 반복+찌꺼기 | 감지·절단 + UI 경고(표시 전용) |

## 2. 알려진 한계 (의도적 보류 — 위험 낮음)

- judge 도착 시 재렌더로 사용자가 **고정한 연결선(pin)이 풀림** → 줄 좌표 재해석으로 보존 가능 (P2)
- 같은 대화 재생성 시 번역·판정 **캐시 없음** (재호출)
- 모바일(<980px)에서 연결선 비활성 (화면상 무의미해 의도적)
- KO 뷰에서 tagger-경로 구역의 줄수 불일치 시 환각 마킹 생략 (오표시 방지 안전장치)
- 동일 문장이 두 줄에 있으면 둘 다 마킹될 수 있음 (희귀)

## 3. 발전 로드맵

### P0 — 발표(07-24) 전 가치 큼
1. **Gold 대조 뷰 + 케이스 브라우저**: ACI valid 20건 드롭다운 → 정답 노트를 4번째 패널/토글로.
   환각(빨강)의 반대축인 **누락**(정답엔 있는데 생성엔 없는 항목)이 눈에 보임 — ROUGE가 재는 것의 시각화. 데이터 로컬에 이미 있음.
2. **검증 스코어카드**: 패널 상단 배지 묶음(환각률·인용 정밀도·미확인 수·교정 후 변화) — 심사자가 한 화면에서 읽는 요약.
3. **교정 diff 뷰**: 원본/교정본 토글을 문장 단위 diff로(삭제=취소선, 재작성=하이라이트) — B안(judge-guided 교정)의 스토리를 화면으로.

### P1 — 제품 스토리 완성
4. **HITL 편집→부분 재판정**: 노트 문장 클릭 편집 후 그 문장만 재판정. "자동 차팅"이 아니라 "검증 보조 도구"라는 프로젝트 정체성의 최종 형태.
5. **케이스 저장/공유 링크**: URL 해시로 재현 — 팀원 리뷰·발표 데모 프리셋.
6. **내보내기**: 노트 복사·Markdown 다운로드·인쇄 스타일(EMR 등재 흐름 암시).

### P2 — 다듬기
7. 접근성: 키보드 내비게이션, aria 라벨. (색맹 대비는 빨강+⚠ 아이콘 병행으로 이미 일부 반영)
8. 연결선 고도화: pin 유지 재해석, 다중 인용 곡선 묶음.
9. 장문 대화(200턴+) 가상 스크롤.

### React 승격 기준
화면 상태 조합 축이 3개(원본/교정 × EN/KO × 케이스)를 넘어 단일 HTML 상태 관리가 버거워지는 시점.
API는 그대로이므로 락인 없음 — 현재는 단일 HTML 유지가 옳다는 판단.
